**Goal:** Die PWA „82-0“ bauen: Starting Five aus echten (Cap-bereinigten) Gehältern draften, Saison als deterministischen Ticker simulieren, mit Trade Deadline und Luxussteuer-Pleite, Tagesrätsel + freies Spiel, Kachel im Hub.

## Global Constraints

- Budget = **140 %** des aktuellen Caps; Preis-Deckel **35 %**; Luxussteuergrenze **120 %**.
- Kader genau **2 G, 2 F, 1 C**; Spieler mit mehreren Positionen zählen für jede.
- 5 Draft-Runden, pro Runde in jedem der **5 Tiers 5 Karten**, Ziel-Mischung 2 G / 2 F / 1 C.
- Karten zeigen **keine Gesamtstärke**.
- 82 Spiele, 41 Heimspiele, Deadline **nach Spiel 50**, Trade-Gehaltsfenster **±15 %**, Verletzung **3–15 Spiele** (vor der Wahl verborgen), Verletzten-Quote **30 %** pro Vorschlag (nur bei überbezahltem Abgang).
- Pleite: **10 %** pro Saison, Zeitpunkt zufällige Siegzahl **60–75**, nur wenn Gehaltssumme in dem Moment > 120 %.
- Stufen: <60 Enttäuschung, 60–69 Playoffs, 70–73 Contender, 74–81 Warriors-Rekord geknackt, 82 Perfektion.
- Dieselbe Five (+ Datum im Tagesrätsel, + Trade-Entscheidung) ergibt immer dieselbe Bilanz.
- Speicherschlüssel beginnen mit `82-0:v1:`.
- Alle Texte in der App auf Deutsch, mit korrekten Umlauten.
- Alle Stellschrauben (Gewichte, Schwellen, Koeffizienten) stehen ausschließlich in `src/config.ts`.
- Datenquelle Stats: `https://raw.githubusercontent.com/sumitrodatta/bball-reference-datasets/HEAD/Data/<Datei>.csv` (Spalte `season` = Endjahr, 2026 = Saison 2025/26). Gehälter ab 2000/01: `https://www.espn.com/nba/salaries/_/year/<Endjahr>/page/<n>` (Endjahr wie oben). Abrufe höchstens 1 pro 3 s, Rohdateien werden lokal zwischengespeichert und nie doppelt geladen.

**Interfaces:**
- Produces (`src/model/types.ts`):
  ```ts
  export type Pos = "G" | "F" | "C";
  export interface SeasonLine { season: number; g: number; x2p: number; x2pPct: number; x3p: number | null; x3pPct: number | null;
    ftm: number; fta: number; ftPct: number; ast: number; tov: number | null; orb: number | null; drb: number | null; trb: number;
    stl: number | null; blk: number | null; allDef1: boolean; allDef2: boolean; }
  export type LeagueAvg = Omit<SeasonLine, "season" | "g" | "allDef1" | "allDef2">;   // pro Team und Spiel
  export interface RawCats { shooter: number; finisher: number; playmaking: number; oreb: number; dreb: number; stl: number; blk: number; allDef: number; }
  export interface Categories { shooter: number; finisher: number; playmaking: number; rebound: number; defense: number; oreb: number; dreb: number; blk: number; }
  ```
- Produces (`src/model/normalize.ts`): `seasonRaw(line: SeasonLine, lg: LeagueAvg): RawCats` – fehlende Werte (`null`) führen zu `Error` mit Saison und Feldname (Schätzwerte werden vorher eingesetzt, Task 6).
- Produces (`src/model/rating.ts`):
  - `seasonScore(r: RawCats): number` (Gewichte aus `CONFIG.seasonWeights`)
  - `pickPeak(lines: SeasonLine[], raws: RawCats[]): { from: number; to: number; raw: RawCats }` – Saisons mit `g < CONFIG.minGames` (35) werden übersprungen; beste 3 aufeinanderfolgende gültige Saisons nach Mittel von `seasonScore`; bei < 3 gültigen Saisons alle gültigen; bei 0 gültigen alle Saisons.
  - `toCategories(peaks: RawCats[]): Categories[]` – je Kategorie Perzentil im Pool → 0–99 (gleiche Werte = gleicher Rang; `rebound` aus `0.4*oreb + 0.6*dreb` raw, `defense` aus `0.5*stl + 0.5*blk + allDef` raw).
  - `strength(c: Categories): number` (Gewichte `CONFIG.strengthWeights`, Ergebnis 0–99)
  - `assignTiers(strengths: number[]): (1|2|3|4|5)[]` – absteigend sortiert, 5 Blöcke à `ceil(n/5)`.
- Produces (`src/model/price.ts`):
  - `pricePct(maxCapShare: number | null, tier: 1|2|3|4|5): { pct: number; source: "contract" | "tier" }` – `min(0.35, share)`; `null` → `CONFIG.tierPricePct[tier]`.
  - `valueResiduals(strengths: number[], pcts: number[]): number[]` – lineare Regression Stärke ~ Preis-% über den Pool, Rückgabe Stärke − Vorhersage.
  - `isOverpaid(residual: number): boolean` – `residual < -CONFIG.overpaidMargin`.

Formeln (`rel(x) = x / (lg.x / 5)`, Effizienz `e2 = x2pPct/lg.x2pPct`, `e3 = x3pPct/lg.x3pPct`, `eft = ftPct/lg.ftPct`, Exponent `k = CONFIG.effExponent`):
- `shooter = 0.75 * rel(x3p) * e3^k + 0.25 * eft`
- `finisher = (2*x2p + ftm) / ((2*lg.x2p + lg.ftm) / 5) * e2^k`
- `playmaking = rel(ast) - 0.5 * rel(tov)`
- `oreb = rel(orb)`, `dreb = rel(drb)`, `stl = rel(stl)`, `blk = rel(blk)`
- `allDef = 0.3` bei 1st Team, `0.15` bei 2nd Team, sonst 0 (im Peak über 3 Saisons gemittelt)

Startwerte in `src/config.ts`: `seasonWeights = strengthWeights = { shooter: .22, finisher: .26, playmaking: .20, rebound: .14, defense: .18 }`, `effExponent: 2`, `minGames: 35`, `priceCapPct: 0.35`, `tierPricePct: {1: .30, 2: .22, 3: .14, 4: .08, 5: .03}`, `overpaidMargin: 8`, `budgetPct: 1.40`, `luxuryPct: 1.20`.

  - `seasonRaw`: doppelte Assists → `playmaking` steigt um 1; schlechtere 2P-Quote (90 % vom Liga-Schnitt) → `finisher` = 0.81 × vorher.
  - `seasonRaw` mit `stl: null` → wirft Fehler mit „stl“ und Saison.
  - `pickPeak`: Saisons 2001–2006 mit Scores [1,5,5,5,2,9], Saison 2005 mit `g=10` (ungültig). Gültige Folge 2001, 2002, 2003, 2004, 2006; bestes Fenster (2003, 2004, 2006) mit Mittel 6,33 → `{ from: 2003, to: 2006 }`.
  - `pickPeak` mit nur 2 gültigen Saisons → beide.
  - `toCategories`: bester Wert → 99, schlechtester → 0.
  - `assignTiers` mit 11 Werten → Tier-Größen [3,2,2,2,2], Tier 1 enthält die 3 höchsten.
  - `pricePct(0.42, 1)` → `{pct: 0.35, source: "contract"}`; `pricePct(null, 3)` → `{pct: 0.14, source: "tier"}`.
  - `valueResiduals` auf perfekter Geraden → alle 0; ein Ausreißer nach unten → negatives Residuum, `isOverpaid` true bei −9.
